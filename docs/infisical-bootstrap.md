# Infisical bootstrap boundary

Infisical cannot retrieve the secrets it needs to start from itself. The deployed
bootstrap file is `/srv/infrastructure/bootstrap/infisical/infisical.env` on the
infrastructure host. Its parent directories are root-owned mode `0700`; the file
is root-owned mode `0600`. It is outside Git and outside Infisical.

The file carries only Infisical startup configuration: the database connection,
Redis connection, site URL, environment setting, encryption key, and auth secret.
The deployment role writes it from the existing protected deployment inputs with
`no_log: true`. A bundled telemetry API key observed in the container is not an
input to this file and is excluded from normal migration.

The former `/srv/infrastructure/secrets/dev/infisical.env` remains available while
the new bootstrap path is staged. The running Infisical container has not been
recreated as part of this boundary change. The Compose environment generated by
the role will reference the bootstrap path on the next attended Infisical deploy.

Workload machine identity credentials, when required, belong in separate
root-owned bootstrap files scoped to their workloads. They must never be placed in
this Infisical startup file, committed to Git, or logged.

Before a future Infisical deploy, verify the bootstrap file exists with mode
`0600`, matches the current active startup values by fingerprint, and passes
`docker compose config --quiet`. Keep the former file until an attended restart
and startup validation succeed. If that restart fails, restore the previous
Compose environment path and recreate only the Infisical project from its
previous known-good configuration.
